# ID-card extraction status

The protected `/register` page accepts one JPEG, PNG, or WebP image up to 10 MB. The browser previews the selection. The server checks the session, request size, actual image bytes, and decoded pixel count, then runs local English OCR with Sharp and Tesseract.js. For the college card format, it extracts labeled date of birth, multiline residential address, and phone, removing common border symbols and stopping the address at the phone label. Repeated identical values are accepted; conflicting values remain empty. The API retains raw OCR text and other parsed fields for its existing contract, while the review page shows only these three suggestions and manual name/roll-number inputs.

The image and result are temporary: the API does not write either to SQLite or disk, and leaving or refreshing the page clears the browser result. The page does not save a reviewed profile. English printed text on a clear card works best; OCR may miss or misread a value, so the three suggestions are editable. Linways retrieval and profile saving remain separate pending modules.

On Windows x64 with Node 24.19.0, `npm.cmd install` installs the pinned `sharp`, `tesseract.js`, and `@tesseract.js-data/eng` packages. The English asset is `node_modules/@tesseract.js-data/eng/4.0.0_best_int/eng.traineddata.gz`; no OCR API key or runtime download is needed. The synthetic card took roughly 350–460 ms for OCR in integration checks. Tesseract may print a nonfatal DPI warning for images derived from SVG.

Verification on 2026-10-04: the revised parser passed a noisy repeated-card sample and the blank-line variation emitted by actual OCR. Four focused browser scenarios passed on desktop Chrome and at 375 px, including real OCR extraction into the five-field review form, manual name/roll entry, image replacement, and failure/retry. The focused browser commands exited cleanly.
